# 一、自己的問題與設計

| 項目 | 我的內容 |
|---|---|
| App 名稱／作者 | 冰箱剩菜食譜靈感機 / **[謝博丞/A113222025]** |
| 目標使用者與情境 | 煩惱每天晚餐要煮什麼的家庭主婦/夫、單身外宿族，或是單純想清空冰箱剩餘食材、避免食物浪費的人。 |
| 想完成的一個任務 | 讓使用者輸入目前擁有的零星食材，由 AI 化身創意主廚，發想出一道料理，並提供菜名、口味特色、所需食材清單與料理步驟。 |
| 輸入資料與範圍 | 使用者手邊現有食材的文字描述（例如：「半顆高麗菜、兩顆雞蛋」），長度限制在 6000 字元以內。 |
| 資訊不足如何處理 | 若使用者輸入的內容明顯不是食材（例如輸入「電腦」、「舊鞋子」或毫無意義的亂碼），要求模型在菜名欄位委婉告知無法製作，並且嚴格將「準備食材」與「料理步驟」的陣列回傳為空清單（空陣列），絕不憑空編造食譜。 |
| 採用 starter 或自行實作 | 採用 starter。理由：老師提供的起點程式碼已經具備完善的防呆檢查、字數限制、API 呼叫流程與錯誤處理架構，這能讓我把開發重心放在核心的 Prompt 設計與 Structured Outputs (JSON Schema) 的欄位規劃上。 |
| 結構化輸出路線 | JSON Schema。理由：起點程式碼已內建配合 `strict=True` 的 JSON Schema 檢查邏輯，且本專題的食譜格式僅需使用字串與字串陣列即可完美呈現，直接定義 Schema 已能滿足需求，無須額外引入 Pydantic。 |
| 相較教師範例的個人設計 | 1. 將單純的摘要任務改為「米其林主廚發想食譜」的創意角色設定。<br>2. 規劃 4 個實用欄位（菜名、口味、食材陣列、步驟陣列），讓輸出像是一張完整的食譜卡。<br>3. 在 UI 端（`FIELD_LABELS`）加入生動的 Emoji，優化使用者的閱讀體驗。 |

## 二、輸出欄位契約

至少兩個有用途的欄位；可自行加列。

| 欄位名稱 | 型別／限制 | 用途 | 畫面標籤 | 如何查原文 |
|---|---|---|---|---|
| `dish_name` | string | 給予這道菜一個吸引人的名稱 | 🍽️ 創意料理名稱 | 檢查菜名是否合理對應到輸入的食材。 |
| `flavor_profile` | string | 用一句話描述這道菜的口味特色 | 🤤 口味特色 | 檢查口味描述是否符合食材屬性（例如是否有提到辣、鹹香或清爽）。 |
| `ingredients_needed` | array of string | 條列出會用到的所有食材與調味料 | 🛒 準備食材 | 檢查原文提到的食材是否都有被納入，且沒有加入過多原文沒提到、難以取得的特殊高價食材。 |
| `cooking_steps` | array of string | 條列出簡單易懂的料理步驟 | 👨‍🍳 料理步驟 | 檢查步驟邏輯是否通順，並且確實使用了前面列出的食材。 |
